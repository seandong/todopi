# F18 `todopi web` 实现计划

**任务：** `tp-0ca49n`（旧 F18）。**Spec:** PRD FR-B1–FR-B4、§3 原则 2（无常驻进程）、§12 安全行；
ARCH-001 / ARCH-002（`src/board/` 是唯一例外）。

## 组成

1. `domain/derive.ts`：`displayColumn(t, derived)` → `open | blocked | in progress | done | closed`（FR-B2 的五列）。
   closed 按 resolution 分 done 与其余；open 且被挡住算 blocked。纯函数。
2. `commands/show.ts`：把「给一个任务建 ShowDto」抽成 `showOf(ctx, task, opts)`，`runShow` 与看板共用——看板一次
   读盘、对每个任务建详情，不能每个任务重读一遍账本。
3. `commands/board.ts`：`runBoard({directory})` → `BoardDto`：全部可显示任务的详情（Log 全量）、各自的列、
   ready 队列（spec §7.4 顺序）、账本根路径、不能显示的 id。只读：不取锁、不写文件、不刷心跳。
4. `output/dto/board.ts`：只搬字段。
5. `output/render/board-page.ts`：单页 HTML，CSS / JS 全部内联，不引用任何外部 URL。三个视图（按列、按容器的树、
   ready 队列）+ 任务抽屉（验收标准、Log、验证证据 = 带 `verify=` 的 done / closed 事件）。页面没有任何写入入口。
   任务内容一律经 `textContent` 进 DOM（不拼 HTML）。数据只从 SSE 来：页面脚本里不用 fetch（ARCH-001 也会拦）。
6. `src/board/server.ts`（新层，登记进 ARCHITECTURE.md）：`node:http` 只监听 `127.0.0.1`；只有 `GET /` 与
   `GET /events`，别的方法 405、别的路径 404。**Host 头必须是 `127.0.0.1:<port>` 或 `localhost:<port>`**——
   防 DNS rebinding（恶意网页把自己的域名解析到 127.0.0.1 就能读看板）。SSE：连上先推一份全量，之后每次变化
   重新算、与上一份不同才推。
7. `src/board/watch.ts`：监听 `.todopi/`（任务目录与 config.yml）；`fs.watch` 抛错、或在 WSL 下（`/proc/sys/kernel/osrelease`
   含 microsoft：drvfs / 9p 上 fs.watch 不报错但不触发）、或用户给 `--poll` 时改为轮询（1 秒，比较文件名 + mtime + size
   的签名）。变化合并 100ms 再重算。
8. `cli.ts`：`web [--port 4747] [--open] [--poll]`。端口严格解析（1–65535）；被占用时退出 1、提示 `--port`、不换端口。
   `--open` 调系统的打开命令（`open` / `xdg-open` / `cmd /c start`），失败只提示。前台运行；不装信号处理——
   SIGINT / SIGHUP 的默认行为就是结束进程，终端关了进程就没了。
9. ARCH-002 收紧：`src/board/` 里每一处 `.listen(` 必须带 `"127.0.0.1"`。

## 要用例钉住的

- 列：五种状态各一例；closed 非 done 的 resolution 进 closed 列。
- 板数据：坏文件不进 tasks、进 invalid；Log 是全量；ready 顺序同 `ls --ready`。
- 服务器：Host 头不对 403；POST 405；未知路径 404；SSE 首推全量；改一个任务文件后推送新数据；内容没变不推。
- 轮询：强制轮询时照样推送。
- 端口被占用：CliError，信息含 `--port`，不在别的端口监听。
- 页面：没有 `http://` / `https://` 外链、没有 `<form`、没有 `fetch(`；只有 GET。
- e2e：真起 `todopi web`，curl 页面与 SSE，改文件看推送，SIGHUP 后进程消失，端口被占用的报错。
