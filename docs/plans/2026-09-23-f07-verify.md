# F07 `verify` 实现计划

> **For agentic workers:** REQUIRED SUB-SKILL: 用 superpowers:executing-plans 逐个 task 执行。步骤用 `- [ ]` 便于跟踪。

**Goal:** `todopi done` 执行任务的 `verify` 命令，失败则拒绝关闭，**超时终止整个进程组**；首次在某仓库执行前要求确认；输出按 FR-D4a 分三处落地。

**Architecture:** 子进程执行与信任记录是新的一层 `src/exec/`，与 `fs/` 同级——只 import `node:*`，不认识 todopi 的格式。门禁判定仍是 `domain/` 的纯函数：`verify` 的**执行结果注入**，判定本身不碰进程。

**Spec:** spec §5.3.3（`done` 行的 `verify=pass|fail|none`）、§6.1（门禁与被拒绝的迁移不写 Log）、§8（信任记录 MUST NOT 在 `.todopi/` 内）、§2（`.cache/` 不提交、可随时删）。PRD FR-D2、FR-D2a、FR-D3、FR-D4、FR-D4a、FR-Q2。

## Global Constraints

- v0.1 零网络、无常驻进程；CLI 不得自动 commit/push/切分支。
- 分层：`commands/` → `output/` → `domain/` → `format/` → `fs/` | `exec/`。`domain/` 不碰进程也不碰 fs；`output/dto/` 从 `domain/` 只能 `import type`（ARCH-020）。
- **新增 `src/exec/` 必须在同一个提交里登记进 ARCHITECTURE.md（ARCH-016）并加 ARCH-021**（`exec/` 只 import `node:*`，镜像 ARCH-019）。边界要在第一个诱惑出现之前就立起来。
- 不得用 `enum` / `namespace` / 装饰器；不得用显式 `any`。
- CLI 的 stdout/stderr 必须是英文；`src/` 里不得有中文字符串字面量（注释可中文）。
- 退出码（FR-Q2）：0 ok / 1 usage / 2 gate / 3 conflict / 4 unsupported version。
- 并发/子进程相关的用例**必须证明它在缺陷存在时会红**。

## 动手前已实测

1. **默认方式杀不掉孙进程。** `spawn(...)` + `child.kill()` 之后孙进程仍然存活；
   `detached: true` + `process.kill(-pid)` 才能全部终止。这是 FR-D2 那条要求的依据，
   我重新测过一遍，结论一致。
2. **`init` 已经把 `.cache/` 写进 `.todopi/.gitignore`**，所以「完整输出不提交」这条
   有现成的地基，e2e 里用 `git status --porcelain` 验证它真的生效。
3. **FR-D3 与 FR-D4a 的张力已由产品负责人拍板并写进 PRD**：`--force` 绕过的是
   「门禁」那次拒绝，**不是 `verify` 的执行**。带 `verify` 的任务在 `--force` 下
   仍然照跑，失败也关闭，但 Log 记 `verify=fail` 与输出尾部——否则「证据必须留在
   diff 里看得见」永远走不到。

## Task 1：`exec/run.ts` —— 以进程组执行，超时终止整个进程组

**Files:** Create `src/exec/run.ts`；Modify `src/ARCHITECTURE.md`、`.harness/arch-rules.json`
**Test:** `tests/exec/run.test.ts`

**Produces:** `type RunResult = { code: number | null; signal: string | null; timedOut: boolean; stdout: string; stderr: string; durationMs: number; truncated: boolean }`、`runCommand(cmd, opts): RunResult`

实现要点，每条都有理由：

- **`spawn("sh", ["-c", cmd])`，不自己切分命令行。** `verify` 是用户写的一行 shell，
  含管道、引号、`&&` 都是常态。自己切等于重新实现一个 shell，而且和用户在终端里
  敲的不是同一个东西。执行前**原样打印**那一行（FR-D4）。
- **`detached: true`** 让子进程自成进程组，`process.kill(-pid, sig)` 才够得着孙进程。
  **代价要写进注释**：detached 的子进程在 todopi 自己被 SIGKILL 时会变成孤儿。
  这与 F05 的租约同属「运行时状态可能被留下」那一类，接受它。
- **升级式终止，不是一记 SIGKILL。** 先向进程组发 SIGTERM，等一个宽限窗口
  （默认 5 秒），再发 SIGKILL。测试框架在 SIGTERM 上刷 coverage / junit；
  直接 SIGKILL 会丢掉那些，还留下半截文件，而半截文件会干扰**下一次** verify。
- **正常退出后也要杀一次进程组。** 直接子进程退出不等于整个组退出——
  跑完之后还活着的孙进程，和超时后留下的一样是泄漏。
- **输出不进内存**。`pnpm test` 能吐几十 MB，全缓存在内存里不合适：完整输出流式写进日志文件，
  内存里只留一个有界的尾部环（1 MiB），并靠 `pipe` 的背压保证目标变慢时也不堆积。
  截断时置 `truncated: true`，报告里说明。
- **Windows 走不通就明说。** CI 只有 Ubuntu，Windows 是尽力而为。
  与其假装支持树终止，不如在 `process.platform === "win32"` 时抛一个明确的错误，
  **不要在没测过的情况下声称支持**。

## Task 2：`exec/trust.ts` —— FR-D4 的按仓库信任

**Files:** Create `src/exec/trust.ts`；Modify `.harness/arch-rules.json`
**Test:** `tests/exec/trust.test.ts`

**Produces:** `trustFilePath(): string`、`isTrusted(repoRoot): boolean`、`recordTrust(repoRoot): void`

- **绝不在 `.todopi/` 里。** spec §8 说得很重：随仓库传播的信任记录等于让仓库
  为自己背书。加一条 ARCH 规则：`src/exec/trust.ts` 不得出现 `ledger.dir` 或
  `.todopi`；e2e 再验一次 `find .todopi -name '*trust*'` 为空。
- **路径要 `realpathSync` 之后再比。** 信任是按仓库路径记的，软链接的检出不该
  看起来像另一个仓库。macOS 上 `/tmp` 与 `/private/tmp` 这一对本会话已经咬过一次。
- **`XDG_CONFIG_HOME` 优先，其次 `~/.config`。** 另外给一个 `TODOPI_CONFIG_DIR`
  覆盖——**用例必须有办法不碰真实的 `~/.config/todopi/trust`**。
- **非 TTY 且没给 `--yes` 要失败关闭，不能挂起。** agent 在管道里跑 `done`，
  阻塞在一个没人看见的提示上是最糟的结果。退出 2 并说清怎么办。
- `--yes` 或 `CI=true` 跳过提示（FR-D4）。

## Task 3：`verify` 门禁

**Files:** Modify `src/domain/gates.ts`、`src/output/render/gate.ts`
**Test:** `tests/domain/gates.test.ts`（追加）、`tests/output/gate.test.ts`（追加）

新增一条拒绝：

```typescript
| { gate: "verify"; code: 2; command: string; exitCode: number | null;
    signal: string | null; timedOut: boolean; tail: string; logPath: string }
```

**执行结果由 `commands/` 注入**（`GateInput.verify?: { command; result }`），
`domain/` 保持纯函数——它不该知道 `child_process` 的存在。

**`verify` 最后跑。** 归属、验收标准、子任务都过了才执行。spec §6.1 的 `done` 行
把 `verify` 写在最前，但那是**效果的顺序不是求值的顺序**：为一个注定要被未勾的
复选框挡下的任务跑十分钟测试，既浪费又出人意料。

报告里的 verify 块要有：原样的命令、退出码/信号/「timed out after Ns」、
输出尾部、**完整日志的路径**。`--json` 的 `actions` 要带那个路径，
让 agent 能自己去读全文——那正是 FR-D2a 说的「据以行动」。

**Files:** Modify `src/commands/done.ts`、`src/commands/transition.ts`、`src/cli.ts`

| 情形 | Log | `.cache/verify/` |

**Files:** Create `tools/e2e/f07-verify.sh`

必测项：

1. `verify` 通过 → 退出 0，Log 是 `verify=pass commit=… dirty=…`，**Log 里没有输出**
