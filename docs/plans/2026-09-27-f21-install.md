# F21 安装：npm 包与 curl 安装器 实现计划

**任务：** `tp-234oft`（旧 F21）。**Spec:** PRD 运行时一行、§12；DECISIONS D006 决策 10、D008 决策 3、D042。

## 先查出来的前提问题

- `bin` 指向 `src/cli.ts`，靠 Node 22 的类型剥离——Node 20 跑不了，也没有 shebang。
- 用到了 Node 20.0 没有的 API：`import.meta.dirname`（20.11）、`readdirSync` 的 `recursive`（20.1）。
- 单二进制里没有磁盘文件：版本号从 `../package.json` 读、verify 的 runner 是另起进程跑 `runner.ts`——两处都会坏。
- 远端 Harness CI 自 09-17 起一直红（没装依赖），没人看。

## 组成

1. `tsconfig.build.json`：逐文件编译到 `dist/`，`rewriteRelativeImportExtensions`；`package.json` 的 bin / files / build / prepack。
2. `src/main.ts` 入口；`src/version.ts` 常量（用例钉住与 package.json 一致）；`exec/run.ts` 找不到 runner 文件时把自己再起一次。
3. Node 20.0 兼容的替换；ARCHITECTURE.md 的约定改掉。
4. `install.sh`（POSIX sh）：D008 决策 3 的清单；下载地址、npm 包规格、latest 的地址可覆盖，测试离线。
5. e2e 认 `TODOPI_E2E_BIN`：整套 Layer-3 能拿装好的包或单二进制跑。
6. `tools/e2e/f21-install.sh`：包的形状、install.sh 的 npm 路径、Node 20.0.0 干净容器（有 docker 时）、二进制路径的全部分支（假资产）。
7. `.github/workflows/install.yml`（有 Node / 无 Node 两个干净容器）、`release.yml`（打标签时构建与发布，npm 发包要 NPM_TOKEN）；
   `harness.yml` 补 `npm ci` 与 git 身份。

## 验证

- `node:20.0.0-slim` 里 `npm i -g` 打出来的包，init / add / ls / claim / done（走 runner）。
- 整套 Layer-3：macOS arm64 单二进制、Node 20.19 的 npm 安装，各 20 个脚本全过；指向 `/usr/bin/false` 时 20 个全挂（确认真在用它）。
- 本地 docker 模拟 install.yml 两个任务（linux-arm64 二进制）与整套 Harness CI（非 root、全新 npm ci、无 git 身份）。
- 合并推送后看远端 CI 真的变绿。发布（打标签、npm 发包）是维护者的动作，不在本任务里做。
