# F06 `done` / `close` / `reopen` 实现计划

> **For agentic workers:** REQUIRED SUB-SKILL: 用 superpowers:executing-plans 逐个 task 执行。步骤用 `- [ ]` 便于跟踪。

**Goal:** 三条关闭/重开命令，门禁不满足时拒绝，并打印一份**不需要再跑别的命令就能据以行动**的报告。

**Architecture:** 门禁判定是 `domain/` 的纯函数，返回**结构化的拒绝**而不是拼好的字符串；报告的措辞在 `output/render/`。写入走 F05 立下的 `withLedgerLock` + `prepareUpdate`。

**Spec:** `spec/todopi-format-v1.md` §5.3.2（验收标准）、§5.3.3（Log 动词 `done`/`closed`/`reopened`）、§6.1（状态迁移与门禁、被拒绝的迁移不得写 Log）、§6.2 不变量 3、§8（租约）。PRD FR-D2、FR-D2a、FR-D3、FR-D5、FR-Q2、FR-Q4。

## Global Constraints

- 格式规格是 normative。**本 feature 已经改过它一次**：§6.1 表格的 `close --as` 改成了 `close --resolution`，因为全局 `--as` 是 actor，撞名时 commander 让全局优先，实测 `todopi close tp-1 --as wontfix` 会把 actor 设成 `"wontfix"` 而 resolution 为空。改的是 CLI 标志名不是格式语义，按 §9 不升 `version`。PRD FR-D5 与命令参考已同步。
- v0.1 零网络、无常驻进程；CLI 不得自动 commit/push/切分支（读 `git rev-parse HEAD` / `git status` 是只读，不违反 ARCH-003）。
- 分层：`commands/` → `output/` → `domain/` → `format/` → `fs/`。`output/dto/` 从 `domain/` 只能 `import type`（ARCH-020）；`format/` 从 `domain/` 只能引 `types.ts`（ARCH-018）；`fs/` 只 import `node:*`（ARCH-019）。
- 不得用 `enum` / `namespace` / 装饰器；不得用显式 `any`。
- CLI 的 stdout/stderr 必须是英文；`src/` 里不得有中文字符串字面量（注释可中文）。
- 退出码（FR-Q2）：0 ok / 1 usage / 2 gate / 3 conflict / 4 unsupported version。
- 涉及并发的改动必须有多进程用例（ARCH-017），且**必须证明它在缺陷存在时会红**。

## 动手前已核实

1. **没有现成的验收标准解析器**——`emit.ts` 只写不读，`validateFile` 不碰这个小节。F06 是第一个消费者。
2. **`logLines` 的小节查找可以抽共享**：`## X` 开始、下一个 `## ` 结束。F09 的勾选写入端也要用它定位具体行，现在抽出来，别写第二份。
3. **`validateFile` 不校验 Log 动词白名单**，spec §5.3.3 也说「未知动词 MUST 被保留并忽略」。所以 `reopened` 不需要在任何清单里登记。

## Task 1：验收标准解析器与共享的小节查找

**Files:** Create `src/domain/acceptance.ts`；Modify `src/domain/validate.ts`（`logLines` 改为复用）
**Test:** `tests/domain/acceptance.test.ts`

**Produces:** `sectionLines(body, heading): { index: number; text: string }[]`、`parseAcceptance(body): Criterion[]`、`type Criterion = { n: number; text: string; checked: boolean; line: number }`

spec §5.3.2 有三个坑，每个都要有用例：

- **嵌套列表项不是验收标准**，也**不占编号**。`  - [ ] child` 缩进了就不算。用例要在两个顶层项之间夹一个嵌套项，断言编号是 1、2 而不是 1、2、3。
- **非复选框行不是标准**。小节里一行普通的 `- some note` 既不算勾上也不算没勾，不能让它把任务判成「未满足」。
- **`[X]` 大写也算勾上**，写入端发 `[x]`。空的或没有这个小节**算满足**。

`line` 字段是给 F09 的勾选写入端定位用的，现在就带上——F09 要改的是某一行的那个方括号，不是重排整段。

- [ ] **Step 1: 写失败的测试**

```typescript
// tests/domain/acceptance.test.ts
const body = [
  "## Acceptance Criteria", "",
  "- [ ] first",
  "  - [x] nested does not count",
  "- [X] second uppercase",
  "- a bare note, not a criterion",
  "", "## Log", "", "- 2026-09-14T09:00:00Z a created",
].join("\n");

test("嵌套项不算标准，也不占编号（spec §5.3.2）", () => {
  const cs = parseAcceptance(body);
  assert.deepEqual(cs.map((c) => [c.n, c.text, c.checked]), [
    [1, "first", false],
    [2, "second uppercase", true],
  ]);
});

test("非复选框行不算标准，也不会让任务变成未满足", () => {
  assert.equal(parseAcceptance("## Acceptance Criteria\n\n- just a note\n").length, 0);
  assert.equal(allChecked(parseAcceptance("## Acceptance Criteria\n\n- just a note\n")), true);
});

test("空的或没有这个小节算满足", () => {
  assert.equal(allChecked(parseAcceptance("")), true);
  assert.equal(allChecked(parseAcceptance("## Acceptance Criteria\n\n")), true);
});

test("line 指向原文里的那一行 —— F09 要靠它定位", () => {
  const cs = parseAcceptance(body);
  assert.equal(body.split("\n")[cs[0]!.line], "- [ ] first");
});

test("小节在 ## Log 处结束，不会把日志行当成标准", () => {
  assert.equal(parseAcceptance(body).length, 2);
});
```

## Task 2：门禁判定（纯函数，返回结构化的拒绝）

**Files:** Create `src/domain/gates.ts`
**Test:** `tests/domain/gates.test.ts`

**Produces:**

```typescript
export type Refusal =
  | { gate: "ownership"; code: 3; holder: string; heldSince: string }
  | { gate: "acceptance"; code: 2; unchecked: Criterion[] }
  | { gate: "children"; code: 2; open: Array<{ id: string; title: string; status: string }> }
  | { gate: "state"; code: 2; message: string };

export function evaluateGates(input: GateInput): Refusal[];
```

**返回结构化的拒绝，不是拼好的字符串。** 措辞属于 `output/render/`——这是 ARCH-020 那条线：报告 DTO 带事实，渲染器造句子。

**门禁顺序决定退出码，必须钉死。** 一个任务既有未勾的标准、又被别人持有时报哪个码？**归属优先，退出 3。** spec §6.1 末段把「assignee 是另一个 actor」单独列为一类拒绝——它是关于**权限**的，而其余门禁是关于**是否就绪**的。用例要同时构造两种条件并断言退出码是 3。

**但报告要列出全部未通过的门禁，不只是第一个**——agent 应该一次把活都修完，而不是修一条重跑一次再看到下一条。所以返回的是 `Refusal[]`，退出码取其中最严重的（3 > 2）。

- [ ] **Step 1: 写失败的测试**，逐条覆盖：

| 情形 | 期望 |
|---|---|
| 全部就绪 | `[]` |
| 有未勾的标准 | `acceptance`，列出**带序号与原文**的未勾项 |
| 有未关闭的子任务 | `children`，列出 id / title / status |
| assignee 是别人 | `ownership`，退出 3，带持有者与其最近写入时间 |
| 未勾 + 别人持有 | 两条都在，退出码取 3 |
| 任务已 closed（对 `done`/`close`） | `state`，退出 2 |
| 任务不是 closed（对 `reopen`） | `state`，退出 2 |
| 子任务本身是 closed | 不算未关闭 |
| 没有子任务、没有标准 | `[]` |

- [ ] **Step 2–4:** 确认失败 → 实现 → 通过
- [ ] **Step 5: 变异测试**。至少四个：归属不优先（退 2）、只返回第一条拒绝、已勾的标准也算未勾、closed 的子任务算未关闭。

## Task 3：FR-D2a 的报告

**Files:** Create `src/output/dto/gate.ts`、`src/output/render/gate.ts`
**Test:** `tests/output/gate.test.ts`

**这是本 feature 最实在的产出。** FR-D2a 的理由写得很直白：这是 agent 唯一能看到的东西，而协议要求它去修活而不是强制通过。报告必须独立回答三个问题：

1. **是哪道门禁**；
2. **具体是什么**——未勾的标准逐条带序号与文本；未关闭的子任务带 id、标题、状态；归属冲突带持有者与其最近一次写入时间；
3. **下一步做什么**——两条出路：修完重跑 `done`，或 `--force --reason <text>`。

注意 `feature_list.json` 的修复提示写的是 `src/output/report/gate.ts`，与本仓库既有的 `dto/` + `render/` 布局不一致。**按既有布局走，并把那条提示改过来。**

## Task 4：`done` 与 `close`

**Files:** Create `src/commands/done.ts`、`src/commands/close.ts`；Modify `src/cli.ts`
**Test:** `tests/commands/done.test.ts`、`tests/commands/close.test.ts`

骨架照搬 F05：`withLedgerLock` → 读 → `evaluateGates` → `prepareUpdate` → commit → `deleteLease`。

**顺序与 `claim` 相反、与 `release` 相同**：先写任务文件、后删租约。理由也相同——崩在中间留下的是「任务已 closed 但租约还在」，那份孤儿租约会被下一次 claim 按 §8 处理；反过来留下的是 committed 的记录跑到本机事实前面。

**D019 的共享租约闸门要一次性用到全部三条命令上。** 那条边界我在 F05 里立了三次、漏了三次，每次都是「只改了被指出的那一个入口」。`done`、`close`、`reopen` 要在**同一个提交**里都带上，不是一个一个加。

Log 行：

```
<ts> <actor> done verify=none commit=<HEAD7> dirty=<bool>
<ts> <actor> closed resolution=wontfix
```

`verify=none` 是 F06 的取值（没有 `verify` 字段时）；F07 会填 `pass`/`fail`。`commit` 与 `dirty` 需要 `fs/git.ts` 加两个只读函数。**不在 git 仓库里时省略这两个 key，而不是写 `commit=unknown`**——一个假的 sha 比没有更坏。

`--force --reason <text>`：

- `--force` 不带 `--reason` 是**用法错误，退出 1**；
- Log 行带 `forced=true`，理由放在 `: ` 之后（可以含空格）；
- **强制时不打印报告**——force 的含义就是「我已经看过了」；
- 理由里的换行要按 §5.3.3 的续行规则处理或拒绝，用例从字符串边界出发测。

**跨 feature 契约**：F04 的 `isUnverified` 读最近一次 `done|closed` 的 `forced=true`。这里写出来的形状必须正好能被它解析。用例：force 关闭 → `ls --closed` 显示 `[unverified]`。

别名（FR-Q4）：`done|finish|complete`、`close|cancel`。用 F04 给 `ready` 做的那个共享选项的写法，别名要接受基础命令的全部选项。别名不计入 20 个子命令上限。

- [ ] **Step 1–5:** 写失败的测试 → 确认失败 → 实现 → 通过 → 提交

用例必须覆盖：四道门禁各自拒绝且**退出码正确**；**被拒绝时 Log 一行都没长**（spec §6.1）；被拒绝时任务文件字节不变、租约不变；`--force` 越过每一道门并记 `forced=true`；关闭成功后租约被删、`doctor` 通过；带 `external` 的任务照常关闭。

## Task 6：端到端

**Files:** Create `tools/e2e/f06-gates.sh`

必测项，每条都对应一条规格条款或一个踩过的坑：

1. 未勾的验收标准 → 退出 2，报告里有**序号与原文**
2. 未关闭的子任务 → 退出 2，报告里有 **id / title / status**
3. 别人持有 → 退出 **3**，报告里有持有者
4. 未勾 + 别人持有 → 退出 **3**，报告里**两道门都在**
5. 被拒绝之后：任务文件字节不变、**Log 没长**、租约不变
6. `--force --reason` 越过门禁 → 退出 0，Log 有 `forced=true` 与理由
7. `--force` 不带 `--reason` → 退出 1
8. 强制关闭后 `ls --closed` 显示 `[unverified]`（F04 的跨 feature 契约）
9. `close --resolution wontfix` → `resolution: "wontfix"`，Log 是 `closed resolution=wontfix`
10. `close --resolution nonsense` → 退出 1
11. `reopen` → `status: "open"`，**`resolution` 与 `assignee` 都不在了**，`doctor` 通过
12. `reopen` 一个未关闭的任务 → 退出 2
13. 别名 `finish` / `complete` / `cancel` 与基础命令等价，且接受同样的选项
14. 输出是英文；`--json` 的 stdout 可解析
15. 在 git 仓库里 Log 带 `commit=` 与 `dirty=`；不在 git 仓库里时这两个 key **不出现**
16. 带 `external` 与怪键的任务关闭后原样保留，`doctor` 通过

改文件用 `node` 而不是 `sed`：BSD sed 不解释替换串里的 `\n`（F04 踩过）。
