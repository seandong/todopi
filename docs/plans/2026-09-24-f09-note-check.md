# F09 `note` / `check` 实现计划

**任务：** `tp-9h2aj9`（旧 F09）。**Spec:** PRD FR-L1、FR-D1、FR-C3、FR-C6；
格式规格 §5.3.2（验收标准）、§5.3.3（`note`、`check`/`uncheck` 的 Log 语法与续行）、
§6.3（`updated`）、§8（租约）。

## 要点

1. **归属判定复用，不重写。** `gates.ts` 里的 `ownershipConflict` 抽到
   `domain/ownership.ts`，`evaluateGates` 与 note / check 共用。这条边界在 F05 立了
   三次、漏了三次（D019）；note / check 是第四、第五个写者。过期的租约不挡（§8）。
2. **`prepareUpdate` 支持正文变换**，在追加 Log 之前应用——翻转与 `check ac=n`
   那一行落在同一次写入里。
3. **翻转只动那一行的那一个字符**，按 `Criterion.line` 定位。嵌套项不占编号、不被动。
4. **Log 文本是「当时的标准文本、截断到 80 字符」**（§5.3.3），按码点截断。
5. **心跳只由持有者刷新**（FR-C3）：租约存在且属于当前 actor 才 `touchLease`。
   `touchLease` 至今没有调用方，而它不看租约是谁的——替别人刷新等于让一次普通写入
   重新获得它并不持有的独占。

## 两个要拍板的判断

- **`check` 对已关闭任务拒绝**（退出 2，与状态门禁同码），**`note` 允许**。`done`
  的验收门禁是按关闭那一刻的勾选状态放行的，事后翻转等于改写那份证据；而事后记一条
  教训正是 `note` 的用途。
- **重复勾选是幂等的空操作**：已勾再 `check` / 未勾再 `--undo` → 退出 0，不写文件、
  不写 Log、说明「已经是这样」。意图已经达成；报错会让在循环里重跑的 agent 平白失败。

## 不在本 feature 里做

自举任务的验收判据是散文。F09 给了勾选的**机制**，但把 13 条 open 任务的散文回填成
勾选项是另一个决定（谁来写、要不要随之改 `verify` 的约定），记进 PROGRESS 待办。
