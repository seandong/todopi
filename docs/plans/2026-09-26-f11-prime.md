# F11 `prime` 实现计划

**任务：** `tp-7o45xj`（旧 F11）。**Spec:** PRD FR-P1、FR-P1a、FR-P1b、FR-P1c、FR-P2、FR-P3、
FR-C5、FR-C6；DECISIONS D010；格式规格 §8（运行时目录）。

## 两个先定下来的

- **token 估算（PRD §15 待决项，用户 2026-09-26 定）：按字符类别加权**——ASCII ÷ 4、CJK × 0.6、
  其余 ÷ 2，向上取整。零依赖、可测。D010 那组数字（145 / 368 / 22）是 tiktoken 量的，**不拿来
  断言估算器**——那是循环论证。PRD §13 要证明的是裁剪顺序，不是绝对大小。
- **会话标识：`--session <id>`，没给就按 actor 记录**（用户说不确定，我定的）。这是最小且可以
  纯增量扩展的一步：以后要从钩子 stdin 读，加一个 flag 即可，不推翻它；各家钩子载荷长什么样
  本来就是 setup 任务的事。记进 DECISIONS。

## 组成

1. `src/domain/tokens.ts`：`estimateTokens(text)`。纯函数，不认识 todopi。
2. `src/format/session.ts`：`recordPrime(ledger, key, now)` / `readLastPrime(ledger, key)`。
   放在 `<lease-dir>/sessions/`——`readHeartbeats` 只认 `<id>.json`，子目录不会被当成租约。
   文件名是键的哈希（会话 id 是任意字符串）；内容里留原键便于排查。键是 `session:<id>` 或
   `actor:<actor>`。**写入尽力而为**：失败只往 stderr 说一句，不改输出、不改退出码——它跑在
   会话开始的钩子里。
3. `src/commands/prime.ts`：
   - 持有的 = `in_progress` 且 `isMine`（FR-C6 的宽松匹配，actor.ts 的注释点名了 prime），按
     `updated` 由新到旧，stale 的也算。
   - 可领数：`isReady` 建在**全部**任务的图上（ls.ts 的同一条理由）。别人持有的 = `in_progress`
     且不是我的。
   - 只读：不写任务文件、不取锁、不刷心跳、不记 Log。唯一的写是运行时目录里的会话时间（有 git 时在 `.git/todopi/leases/sessions/`，没有时按 spec §8 回退到 `.todopi/.cache/`）。
   - 预算循环在命令里：建 DTO → 渲染 → 估算 → 收紧 → 重渲染。
4. `src/output/dto/prime.ts`、`src/output/render/prime.ts`。`--json` 输出**裁剪之后**的 DTO，
   加一个 `truncated` 标记——「同样的内容」字面成立。
5. `cli.ts`：`--budget <n>`（严格整数解析，`0x10` 的教训）、`--full`、`--session <id>`。
6. `tools/e2e/f11-prime.sh`：真 git 仓库里跑；会话文件落在 `.git/todopi/leases/sessions/`，
   跑完 `git status` 干净。

## 要用例钉住的不变量

- **指针永远是最后一行，原样**：对 0..800 的每个预算都成立。
- **裁剪顺序**：先丢已勾的标准，再把 Log 从 2 条减到 1 条；**未勾的标准永不丢**。第一个持有的
  任务收紧到底仍超预算时**照样输出**（未勾的标准正是推送的意义），有一个故意超预算的用例。
- **多个持有任务**：装不下的退化为一行「另有 N 个你持有的任务」加命令。
- **协议不出现（D010）**：用白名单断言——每一行都是任务标题、标准、Log、空行或指针。
- 纯 Markdown，没有 ANSI；结尾恰好一个换行。
- 账本里有解析失败的任务时不崩。
- `--full`：不受预算约束，节按 FR-P3：当前任务、别人持有的、ready 前 5 条、计数、最近关闭 3 条
  （按 `updated` 由新到旧）。
- 没有账本时照其他命令一样非零退出；setup 任务的钩子需要自己兜底（记下，不在这里改）。
