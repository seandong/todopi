# F12 `handoff` 实现计划

**任务：** `tp-sch6q1`（旧 F12）。**Spec:** PRD FR-H1、FR-D4、FR-C6、FR-P1b；格式规格 §5.3.3（`handoff`
动词，text = 摘要）、§8（运行时目录）。

## 报告（展示用宽松匹配，FR-C6）

1. **我的进行中任务里，最近一小时没有 Log 的。**
2. **自上次 prime 以来我新建的任务**：上次 prime 时不在账本里、且 `created` 那条 Log 的 actor 算我的。
3. **自上次 prime 以来 verify 变了的任务**——**所有**任务，不只是我的：FR-D4 担心的正是别人（手改、
   被合并的 PR）改了 verify 而我下次 `done` 会照跑它。

「上次 prime」按 `--session <id>` 找，没给按 actor（与 prime 同一个键，D032）。

## 为什么要快照，而不是翻 Log

`edit --verify` 会记 `edited fields=verify`，但手改文件和合并进来的 PR 不经过 CLI、不留这条 Log——而
那两种正是 FR-D4 的威胁。所以 **prime 记会话时间时顺带记一份快照**：每个任务 id → verify 的哈希。
handoff 拿当前值比。快照里没有的 id 就是 prime 之后出现的（新建的或合并进来的）。旧格式的会话记录
（没有快照）或从没 prime 过：第 2、3 节说明「没有可比的基准」，不猜。

## 写入（严格匹配）

向 `assignee` 恰好等于当前 actor 的每个进行中任务追加 `handoff: <摘要>` 并刷新心跳（走
`writeAsWorker`）。摘要由 CLI 生成：`<已勾>/<总数> criteria checked`（没有勾选项时写 `no checkbox
criteria`）。**不释放认领**。某个任务写失败（冲突等）不影响其余，最后以第一个失败的退出码退出。

`--check`：只输出报告，不写任何东西，退出 0（给钩子用；报告本身出错也退出 0？——不：账本都读不了
时照常非零，与 prime 一致）。

## 要钉住的

- 报告三节的判据各有正反例；verify 手改（不经 CLI）也被发现。
- 写入只落在 assignee 严格等于 actor 的任务；同机别的 agent 持有的（宽松算我的）出现在报告里但不写。
- 不释放认领：handoff 之后 status / assignee / 租约都还在，心跳更新了。
- `--check` 之后整个账本与运行时目录逐字节不变。
