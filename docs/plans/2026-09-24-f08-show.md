# F08 `show` 实现计划

**Goal:** `todopi show <id>` 打印一个任务的全部 frontmatter、带序号的验收标准、
最近 5 条 Log 及总数；`--full` 展开全部 Log，`--tree` 显示父链与子任务进度，
`--json` 输出单个对象。

**任务：** `tp-djqkva`（旧 id F08）。**这是自举之后第一个用 todopi 自己管的
feature**，走 AGENTS.md 的新回路：claim → 干活 → 人核对判据 → 提交（含 claim 的
账本改动）→ `todopi done` → 提交账本与 PROGRESS → `make clean-check`。

**Spec:** PRD FR-T3、spec §5.3（正文四个 H2）、§5.3.3（Log 语法与续行）、
§7.1（children）、§7.4（排序）。

## 全局约束

- 分层：`commands/show.ts` → `output/dto/show.ts` → `output/render/show.ts`；
  领域逻辑放 `domain/`，纯函数。
- ARCH-020：`output/dto/` 从 `domain/` 只能 `import type`。
- CLI 输出英文；`--json` 的 stdout 必须是干净的 JSON。
- 非法任务文件的容忍名单照抄 `ls`（`invariant-2/3/6` 照常渲染，其余拒绝并指向
  doctor），**不另起一个校验器**。
- id 不存在的措辞与 `claim` / transition 一致。

## 领域层的真缺口：Log 续行

`logLines` 只取 `- ` 开头的行，**续行被丢掉**。而 F07 的 forced done 已经在写
续行了（最后 512 字节的 verify 输出）。spec §5.3.3：「A multi-line text continues
on following lines indented by two spaces; readers join them with `\n`」。

新增 `logEntries(body)`，放在 `logLines` 旁边。**不改 `logLines`**——
`isUnverified` 与 doctor 都在用它。

## 三处容易写错

1. **最近 5 条是 `slice(-5)`**：7 条 → 显示第 3–7 条、`total: 7`。写成
   `slice(0, 5)` 必须有用例变红——「显示了 5 条」这种断言放得过它。
2. **`--tree` 的父链防环、防悬空**：沿 `parent` 往上走带 visited set；
   父 id 不在索引里显示为 missing，不崩。子任务按 §7.4 排序，各带自己的进度。
3. **`--json` 是单个对象**，不是数组——FR-T2 的「数组」只约束 `ls`。DTO 扩展
   `TaskDto`，补上它没有的 `verify` 与 `external`（show 要显示全部 frontmatter）。

## 已知张力，不在本 feature 里改

spec §5.3 说未识别的小节 MUST 被读者忽略。**本仓库自举生成的任务都有
`## Repair` 段，`show` 因此看不见它**。`show` 是 reader，不越过规格——读 Repair
继续用 `cat`（AGENTS.md 已写明），这条观察记进 PRD §15。
